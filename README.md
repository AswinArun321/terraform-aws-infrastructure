Production-style Infrastructure as Code (IaC) repository that automates the provisioning of an isolated, multi-tier AWS application environment using **Terraform**.

The infrastructure orchestrates networking, serverless container compute (ECS Fargate), layer-7 load balancing (ALB), and a private managed relational database (RDS PostgreSQL). A single root configuration provisions completely isolated **development (`dev`)** and **staging (`staging`)** environments using per-environment variable files and remote S3 backend state with S3-native locking.

> [!IMPORTANT]
> **Project Deployment Status & Zero-Cost Notice:**  
> This project is developed and validated following a strict **Zero-Cost methodology**. All Terraform modules, root configurations, security groups, and policies are fully implemented, formatted, and verified through **local static analysis and configuration validation** (`terraform validate`, `tflint`, `checkov`). **No paid AWS infrastructure has been created, provisioned, or activated in the cloud.** All operational benchmarks and performance metrics detailed herein represent target design specifications and ephemeral testing baselines.

```text
                                     │ HTTP (Port 80)
                                     ▼
                       ┌───────────────────────────┐
                       │ Application Load Balancer │
                       │    (Public Subnet AZ-a,   │
                       │     Public Subnet AZ-b)   │
                       └─────────────┬─────────────┘
                                     │
                                     │ HTTP (App Port 8000)
                                     ▼
                 ┌───────────────────────────────────────┐
                 │       AWS ECS Fargate Cluster         │
                 │ ┌───────────────────┐ ┌─────────────┐ │
                 │ │ Task (AZ-a)       │ │ Task (AZ-b) │ │
                 │ │ Private Subnet    │ │ Private Sub │ │
                 │ └─────────┬─────────┘ └──────┬──────┘ │
                 └───────────┼──────────────────┼────────┘
                             │                  │
         Outbound HTTPS 443  │                  │  PostgreSQL TCP 5432
         (ECR, CW, Secrets)  │                  │  (SSL Required)
                 ▼           │                  ▼
         ┌───────────────┐   │         ┌───────────────────┐
         │  NAT Gateway  │   │         │  RDS PostgreSQL   │
         │(Public AZ-a)  │◄──┘         │(Private DB Subnet)│
         └───────┬───────┘             └───────────────────┘
                 │
                 ▼
         ┌───────────────┐
         │ Internet GW   │
         └───────────────┘
```

### Traffic & Security Model
1. **Public Ingress:** Public clients communicate exclusively with the internet-facing **Application Load Balancer (ALB)** over port 80 (restricted to allowed ingress CIDRs; defaults to empty list).
2. **Reverse Proxy to Fargate:** The ALB reverse-proxies requests to container tasks running on **AWS Fargate** in private application subnets over port 8000.
3. **Private Database Air-Gap:** The **Amazon RDS PostgreSQL** instance resides strictly within dedicated private database subnets with `publicly_accessible = false` and has **zero route to the internet** (`0.0.0.0/0` does not exist in the DB route table).
4. **Least-Privilege Security Groups:** Standalone security group rules ensure that:
   - ALB accepts HTTP 80 from allowed CIDRs and egresses only to the ECS Task SG.
   - ECS tasks accept traffic strictly from the ALB SG and egress to RDS on port 5432 and outbound HTTPS 443 via NAT for AWS APIs.
   - RDS accepts port 5432 traffic strictly from the ECS Task SG.
   - Default VPC Security Group denies all inbound and outbound traffic (`aws_default_security_group`).
5. **RDS-Managed Password Rotation & Injection:** Database credentials are generated by AWS Secrets Manager via `manage_master_user_password = true`. The ECS Task Execution IAM role retrieves the secret at runtime and injects it into the container environment (`DB_PASSWORD`) without passwords ever appearing in code, tfvars, state, or task definitions.
6. **Encryption in Transit & Query Logging:** RDS enforces TLS via parameter group `rds.force_ssl = 1` and logs queries with `log_statement = "all"`.

## 4. Terraform Modules Overview

Every module contains explicit provider constraints (`versions.tf`), fully typed variables with validation (`variables.tf`), outputs (`outputs.tf`), and documentation (`README.md`):

1. **[`modules/vpc`](modules/vpc):** Provisions a 3-tier VPC across 2 Availability Zones. Subnets are computed dynamically using `cidrsubnet()`. Disables `map_public_ip_on_launch` by default and provisions an `aws_default_security_group` that blocks all ingress and egress. Private DB subnets have zero internet route.
2. **[`modules/security-groups`](modules/security-groups):** Implements least-privilege traffic flow using standalone `aws_vpc_security_group_ingress_rule` and `aws_vpc_security_group_egress_rule` resources, avoiding circular security group dependencies.
3. **[`modules/alb`](modules/alb):** Deploys an internet-facing Application Load Balancer with `drop_invalid_header_fields = true`, deletion protection enabled by default, and an IP-type Target Group (`target_type = "ip"`) configured for ECS Fargate containers.
4. **[`modules/rds`](modules/rds):** Provisions a PostgreSQL database in isolated private subnets with at-rest KMS storage encryption, automated master password management in AWS Secrets Manager, IAM DB authentication, Performance Insights, parameter group SSL enforcement (`rds.force_ssl = 1`), and query logging.
5. **[`modules/ecs`](modules/ecs):** Orchestrates an AWS Fargate cluster, task definition with explicit `runtime_platform` (`X86_64`), IAM execution role with scoped Secrets Manager access, CloudWatch log group with explicit retention, and ECS service with deployment circuit breaker rollback.

## 5. Security & Governance Best Practices

- **Zero Hardcoded Credentials:** Master passwords are created and rotated automatically by RDS via AWS Secrets Manager. Secrets are injected directly into container tasks via IAM execution role permissions.
- **Network Air-Gapping:** The database layer has no public IP addresses and no default route to the Internet Gateway.
- **Restricted Default Ingress:** ALB ingress CIDRs default to an empty list (`[]`), requiring explicit configuration in environment `.tfvars`.
- **Default Security Group Neutralization:** The default VPC security group explicitly denies all inbound and outbound traffic.
- **KMS Encryption at Rest:** ECR repository is encrypted with KMS (`encryption_type = "KMS"`). S3 state bucket enforces KMS encryption (`aws:kms`). RDS storage is KMS encrypted (`storage_encrypted = true`).
- **S3 Bucket Hardening:** State bucket enforces TLS-only access (`aws:SecureTransport = "false"`), blocks all public access, expires non-current versions after 30 days, aborts incomplete multipart uploads after 7 days, and emits EventBridge notifications.
- **Deletion Protection:** Enabled by default on both Application Load Balancers and RDS instances to protect against accidental termination.

## 7. Continuous Integration (CI/CD Pipeline)

Automated quality gates run on every pull request and push to `master` via [GitHub Actions](.github/workflows/terraform-checks.yml):
- **Formatting Gate:** `terraform fmt -check -recursive`
- **Validation Gate:** `terraform validate` across `bootstrap/` and `infra/`
- **Linter Gate:** [TFLint](https://github.com/terraform-linters/tflint) with AWS ruleset
- **Vulnerability Scanner:** [Trivy](https://github.com/aquasecurity/trivy) scanning for misconfigurations
- **IaC Security Scanner:** [Checkov](https://www.checkov.io/) validating compliance with 140+ CIS and AWS security benchmarks (**132 Passed, 0 Failed**)
- **Secret Detection:** [Gitleaks](https://github.com/gitleaks/gitleaks) scanning commit history for leaked credentials
- **Zero-Deploy Guarantee:** The workflow strictly performs static analysis and contains no deployment or apply steps.

## 8. Cost Considerations (Dev vs. Staging)

When deployed in live accounts for temporary verification, costs are kept minimal by running ephemeral sessions:

| Dimension | Development (`dev`) | Staging (`staging`) |
|---|---|---|
| **VPC CIDR** | `10.0.0.0/16` | `10.1.0.0/16` |
| **ECS Task Sizing** | 1 task (0.25 vCPU, 0.5 GB RAM) | 2 tasks (0.5 vCPU, 1.0 GB RAM) |
| **RDS Instance Class** | `db.t4g.micro` (Single-AZ) | `db.t4g.small` (Single-AZ) |
| **RDS Storage** | 20 GB gp3 | 30 GB gp3 |
| **Backup Retention** | 1 day | 7 days |
| **Deletion Protection** | Enabled | Enabled |
| **Final Snapshot** | Skipped | Created on destroy |

For an in-depth breakdown of hourly and monthly costs, consult [docs/COST-ESTIMATE.md](docs/COST-ESTIMATE.md).
